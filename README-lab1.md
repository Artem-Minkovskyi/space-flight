# Space Flight — Лабораторна робота №1

## The Event Loop Is the Game Loop

### 1. Мета роботи

Метою лабораторної роботи є дослідження принципів роботи Event Loop у JavaScript шляхом створення браузерної гри Space Flight.

Під час виконання роботи було реалізовано ігровий цикл із фіксованим кроком симуляції, обробку клавіатури, фізику руху космічного корабля та відображення графіки за допомогою Canvas 2D.

Також було проведено три експерименти для дослідження впливу блокування головного потоку, використання setInterval() та порівняння Fixed Timestep і Variable Timestep.

### 3. Опис проєкту

Space Flight — це браузерна гра, у якій користувач керує космічним кораблем у двовимірному просторі.

Ігрове поле містить зоряне тло, координатну сітку та корабель із візуальним ефектом двигуна.

У верхній частині ігрового поля відображаються показники продуктивності:

- Simulation — кількість кроків симуляції за секунду.
- Render — кількість відображених кадрів за секунду.
- Frame Time — час виконання рендерингу в мілісекундах.

### 4. Керування грою

| Клавіша | Дія                      |
| ------- | ------------------------ |
| W або ↑ | Рух уперед               |
| S або ↓ | Гальмування та рух назад |
| A або ← | Поворот ліворуч          |
| D або → | Поворот праворуч         |

Корабель може перетинати межі ігрового поля та з'являтися з протилежного боку.

### 6. Реалізація основних компонентів

**loop.js**

Модуль відповідає за організацію ігрового циклу. У фінальній реалізації використовується requestAnimationFrame() та акумулятор часу.

Симуляція виконується з фіксованим кроком 1/60 секунди, а рендеринг відбувається відповідно до частоти оновлення браузера.

**input.js**

Модуль відповідає за обробку натискань клавіш. Для зберігання стану клавіш використовуються структури Set.

Реалізовано методи:

- isDown() — перевіряє, чи утримується клавіша.
- justPressed() — перевіряє момент натискання.
- endStep() — очищує стан одноразових натискань.
- destroy() — видаляє обробники подій.

**sim/ship.js**

Містить логіку фізики корабля: прискорення, поворот, гальмування, опір руху та обмеження максимальної швидкості.

Функція integrate() повертає новий стан корабля та не виконує операцій із DOM або Canvas.

**sim/arena.js**

Відповідає за переміщення корабля на протилежний бік ігрового поля після перетину його меж.

**render/canvas.js**

Відповідає за налаштування Canvas 2D, зміну розмірів полотна та підтримку Device Pixel Ratio.

**render/draw.js**

Містить функції малювання ігрової сцени, зоряного тла, координатної сітки та космічного корабля.

**main.js**

Основний модуль, який об'єднує симуляцію, обробку клавіатури, рендеринг та оновлення показників продуктивності.

### 7. Експерименти

#### Експеримент №1. Блокування головного потоку

Мета: дослідити, як тривале виконання синхронної операції впливає на роботу ігрового циклу.

Для експерименту було додано штучне блокування головного потоку на 100 мілісекунд кожні 5 секунд.

Блокування реалізовано за допомогою циклу while, який виконується до закінчення заданого часу.

Під час експерименту спостерігалися затримки виконання кадрів. Це демонструє, що синхронні операції блокують головний потік JavaScript, через що браузер не може своєчасно виконувати рендеринг та обробляти інші завдання.

**Висновок:** тривалі синхронні операції негативно впливають на плавність роботи гри та можуть спричиняти падіння FPS.

#### Експеримент №2. Порівняння requestAnimationFrame() та setInterval()

Мета: дослідити стабільність роботи ігрового циклу при використанні setInterval().

Для експерименту початкову реалізацію ігрового циклу було замінено на setInterval() з інтервалом 16 мілісекунд.

Додатково було реалізовано вимірювання відхилення фактичного інтервалу між викликами від запланованих 16 мілісекунд.

Отримані результати:

| Вимірювання | Кількість вимірювань | Середнє відхилення | Максимальне відхилення |
| ----------- | -------------------: | -----------------: | ---------------------: |
| 1           |                  623 |            0,57 мс |                3,90 мс |
| 2           |                  562 |            2,39 мс |              776,10 мс |

Під час попередніх перевірок також було зафіксовано максимальні відхилення до 984,50 мс.

Висновок: setInterval() не гарантує точного виконання через однакові проміжки часу. На роботу таймерів впливають завантаженість головного потоку та механізми обмеження таймерів браузером у фонових вкладках.

requestAnimationFrame() краще підходить для організації ігрового рендерингу, оскільки синхронізує оновлення з циклом відображення браузера.

#### Експеримент №3. Fixed Timestep та Variable Timestep

Мета: порівняти поведінку фізичної симуляції з фіксованим та змінним кроком часу.

Для Variable Timestep симуляція виконувалася один раз за кадр. Значення dt визначалося за фактичним часом між двома кадрами.

Для Fixed Timestep використовувався постійний крок симуляції 1/60 секунди та акумулятор часу.

Під час тестування корабель рухався вперед протягом 5 секунд.

Отримані результати:

| Показник                                      | Variable Timestep | Fixed Timestep |
| --------------------------------------------- | ----------------: | -------------: |
| Час вимірювання                               |            5,00 с |         5,00 с |
| Початкова координата X                        |            453,50 |         453,50 |
| Кінцева координата X                          |            695,03 |         530,98 |
| Кінцева координата Y                          |            261,74 |         237,39 |
| Відстань між початковою та кінцевою позиціями |            242,57 |          90,49 |

Отримані значення відрізняються. Однак вимірювання не проводилися за підтверджено однакових умов навантаження CPU, тому ці результати не можна вважати контрольованим доказом переваги одного методу.

**Висновок:** Fixed Timestep забезпечує стабільний крок фізичної симуляції незалежно від частоти рендерингу. Variable Timestep залежить від фактичного часу між кадрами, тому зміни продуктивності можуть впливати на результати фізичних обчислень.

### 8. Загальний висновок

Під час виконання лабораторної роботи було створено браузерну гру Space Flight із використанням JavaScript, HTML5 Canvas та Vite.

Було реалізовано:

- ігровий цикл із фіксованим кроком симуляції;
- обробку клавіатури;
- фізику руху космічного корабля;
- інтерполяцію стану об'єктів;
- відображення графіки через Canvas 2D;
- вимірювання продуктивності гри.

Проведені експерименти продемонстрували вплив блокування головного потоку на плавність гри, особливості роботи setInterval() та відмінності між Fixed Timestep і Variable Timestep.

У результаті було досліджено, чому розділення симуляції та рендерингу, а також використання фіксованого кроку часу є важливими для створення стабільних браузерних ігор.
